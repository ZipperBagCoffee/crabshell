# Verification runner reuse, timing and output

Read the relevant section when Run Mode in `SKILL.md` points here.

## Reuse and timing

**Reuse.** A selected check reuses its PASS when its fingerprint is among the ones it passed with (`passHistory`, the last `passHistory` passes, default 10). The fingerprint covers the record schema, the entry's `type`, `command`, `contract` and `timeout`, the program it runs (a project file by content, a PATH program by size and time), the runner modules that judge it, the platform and architecture, and the content of every input (folders by their sorted names). A pass is not recorded when one of its inputs was written while checks ran.

Never reuse failed or timed-out checks, manual entries, empty input records, `always: true`, `reuse: false`, explicit entry IDs, or changed tests requiring fail-before (with `--fail-before`). Runs that select every check reuse unchanged passes too: the fingerprint already covers the entry, the runner and every input. `--no-reuse` forces all selected checks to execute. Discovery entries can use `reuseExclude` to disable reuse for individual files; use these controls for external tools or other untracked inputs (see [manifest entry controls](manifest-entries.md)).

**Failed runs.** Passing checks still refresh their traced files, pass fingerprints and input hashes when another check fails; reused passes retain their execution evidence. A failed check keeps its prior dependency record (or its traced files when no prior files exist) and its `passHistory`, and gets an ISO `lastFailedAt` and a `failKey` (the fingerprint it failed on). `lastFailedKind` is `check` for a failed check, or `fail-before` when the check passes but its HEAD comparison fails; a check failure takes precedence. The next `--changed` selects it with reason `failed in the last run`, even with no file changes. Reuse and coverage cannot clear a failure. After saving the map, stderr names checks with unresolved failure marks.

An executed PASS clears a `check` mark. It clears a `fail-before` mark only with fail-before enabled in a `--changed` run whose changed-file list is known, and only when the entry is no longer a `failBeforeTargets()` target or its comparison passes (including a hash-matched exemption). Explicit-ID, full and `--no-fail-before` runs, unknown Git changes and unresolved/manual comparisons keep the prior `lastFailedAt`, `lastFailedKind`, dependency `files`, and record no new pass; the latest execution duration can still be recorded.

**Coverage.** `coveredBy` names a check that also runs this test. When both are selected and the child has a nonempty file record, the covering check runs first. Its executed or reused PASS records the child as `status: "PASS"`, `coveredBy: "<id>"`, `durationMs: 0`, without `reused` or a pass fingerprint of its own. For a child with `reuse: false`, `reuseExclude` or `always: true`, only a covering check that actually executed and passed in this run permits coverage; a reused PASS makes the child execute. A failed or timed-out covering check also forces the child to execute, even if it has an older cached PASS. Results keep manifest order. Established dependency records and execution durations are retained. A missing record, missing `files` or empty `files` makes the child execute to establish its own inputs first.

Coverage is disabled when the covering check is absent, an ID is explicitly named, `--no-reuse` is given, or the child test changed and fail-before is enabled. This last rule conservatively includes changed tests before their newly traced inputs are known. A covered result cannot cover another check in a chain; that child executes. Unknown IDs and coverage cycles are manifest errors. A covered entry or discovered file must have no `contract.assertions`, and every path in its `contract.forbiddenChanges` must also occur in the covering check's list; violations name both IDs. Declaration shapes are in [manifest entry controls](manifest-entries.md).

`--dry-run` prints JSON without executing checks: `reasons` for each selection, `wouldReuse` and `wouldCover` counts, and `estimatedSeconds` from known execution durations (unknowns contribute zero). With `--changed` and fail-before enabled, `failBeforeTargets` counts selected changed tests whose recorded inputs cover changed non-test files, excluding matching SHA-256 exemptions. Each adds `lastDurationMs` twice for a test present in HEAD (baseline and attempt), once for a new test; a Git lookup error assumes twice. `--no-fail-before` and full mode add no comparison time and report zero targets. Coverage estimates assume the covering check passes and exclude the covered child's duration; selection reasons stay unchanged.

Results carry the actual `durationMs`, including time spent timing out. An `ETIMEDOUT` result also carries `timedOut: true` and preserves the previous `lastDurationMs` in the map, or leaves it absent if no duration was recorded. Reuse and coverage report zero without replacing it. Failed, timed-out and covered checks never add a pass fingerprint.

## Manifest changes and records

A change to an entry field that decides the run (`type`, `command`, `contract`, `timeout`) or to the program it runs changes that check's fingerprint, so only that check runs again; names, notes and selection hints do not. Top-level fields reach checks only through their inputs: `changed.global` adds files to every check, `exclude` removes paths from the snapshot. Each record (`test-map.json`, schema 3) keeps the check's input kind — `traced` (files it read, from the trace), `declared` (`inputs`, for a program the runner cannot trace) or `project` (inputs unknown: the whole project, for that check only) — its input hashes, `passHistory`, pass durations (their median ranks checks and marks heavy ones), runs and last failure. A record of another schema counts as missing, so every check runs once after a schema change; new checks always run; removed entries need no run.

## Output and saved results

Default stdout shows a one-line verdict: executed/reused counts, `N covered by <id>` (or `N covered by other checks` for multiple covering IDs), manual checks waiting for a person, elapsed seconds; zero parts are omitted. Covered checks count as PASS, not as executed. Failures show their first failure line and last five stderr lines. Empty selection says `No checks selected — nothing changed that a check reads.` and exits 0. `Verification Results: PASS: N / FAIL: N / Manual: N / Total: N` remains.

For a person's nonempty run (full, `--changed`, `--json` or explicit ID), the full array is saved atomically to `last-run.json` beside the runner: `Full results: <path>` confirms success; `Full results: not saved (<error>)` reports failure. Internal calls with `CRABSHELL_VERIFY_JSON=1` or `--no-fail-before`, and runs producing no results, leave the previous file byte-identical and print no `Full results:` line. Read the saved file instead of rerunning. `--json` or `CRABSHELL_VERIFY_JSON=1` also prints the current array; `--no-fail-before` does so for older guards. `--changed --json` does **not** count for the commit gate: use the declared `--changed` command and its saved JSON.
